  File: frontend\src\pages\inventory\Fleet.tsx (the BusModal form)

  What was wrong:

      Fetch ALL users from the server (every user in the system)
      Then filter in the browser: only show users where role = 'driver'

    most of them are thrown away in the browser.

STEP 5 — FIXED the driver fetch to filter on the server instead.
  File changed: frontend\src\pages\inventory\Fleet.tsx

  Before:
    queryFn: () => userApi.list()
    drivers = users.filter(u => u.role === 'driver' || u.department === 'fleet')

    drivers = usersRes?.data?.data ?? []

  Result: Only driver-role users are returned from the server.
  Faster, more efficient, and consistent with other pages.

STEP 2 — FOUND that "Request WO" button was completely fake. [CRITICAL]
  File: frontend\src\pages\inventory\PMS.tsx

  What was wrong:
    When you click "Request WO" on any bus, it opens a modal.
    You fill in the priority and description, then click "Submit WO Request".

    The Submit button was doing this:
      onClick={() => setSubmitted(true)}

    setSubmitted(true) just changes a local flag to show a success screen.
    NO HTTP request was ever sent to the server.
    NO Work Order was ever created in the database.
    The success screen "WO Request Sent" was completely fake.

    Impact: Any mechanic or service adviser who requested a Work Order from
    the PMS page would see a success message, but nothing would appear in
    the Work Orders list. The entire PMS → Work Order safety chain was
    silently broken.

STEP 3 — FIXED the Submit button to actually call the API.
  File changed: frontend\src\pages\inventory\PMS.tsx

  Added: import of workOrderApi
  Added: a mutation (API call) that sends:
    POST /api/work-orders with:
      bus_id      = the bus that needs maintenance
      description = the text entered in the WO Description field
      priority    = the priority level selected (Low / Medium / High)
      type        = 'preventive'

  Changed:
    Before: onClick={() => setSubmitted(true)}
    After:  onClick={() => mutation.mutate()}

  Added:
    • Loading spinner on the button while request is in-flight
    • On success → invalidates Work Orders list cache, THEN shows success screen
    • On error → shows error toast with the server's error message

  Result: Clicking "Submit WO Request" now creates a real Work Order in the
  database. It immediately appears in the W.O (Work Orders) page.
